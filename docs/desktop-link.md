# Desktop link v1

Enable Phone Remote in Lokal settings, open its Linked devices panel, and choose Pair a phone. On Android open You → Devices (also available in settings and optional onboarding), then scan the QR code or enter the desktop address and code. Both devices must be on the same local network. The code expires after two minutes and can be used once. Revoke a phone from the desktop panel to invalidate its token and close its socket.

The desktop panel can control connected phone playback or transfer playback in either direction. Android can select the desktop as its playback target while retaining the existing player interface. Missing phone files are copied to the desktop only with the phone's explicit download-sharing option; otherwise handoff reports the unavailable songs. Imported desktop-only songs remain placeholders until streamed, cached, or downloaded. Original files are never moved or deleted by linking.

Pairing and synchronization are separate: the phone previews the merge before enabling it. History merges by event ID. Library mutations use append-only operation IDs, hybrid logical clocks, per-field conflict resolution, explicit playlist tombstones, stable playlist UUIDs, and numeric positions with deterministic track-key ordering. Missing rows never imply deletion. Imported listening events do not invoke external scrobblers. Sync cursors are scoped to desktop and user profile. Theme adoption requires an explicit setting on the receiving device.

The LAN protocol uses `_lokal._tcp.local` discovery, sharing multicast sockets with Cast. Pairing is POST `/api/remote/pair`; playback and journal exchange use `/api/remote/ws`. Messages have `{v:1,type,id,ts,body}`. Request IDs correlate replies. State messages carry semantic changes and seeks; clients extrapolate position from `positionAt`. Sockets use heartbeat and Android reconnect/backoff; manual address and legacy polling remain available.

Pairing URLs, QR codes and discovery use the same LAN interface selection. Node reports active interfaces; Ethernet/Wi-Fi addresses are preferred, while recognizable Wintun, VPN, Tailscale and host-only VM/container adapters are omitted from automatic discovery. Loopback, link-local and invalid IPv4 addresses are excluded. Carrier-shared addresses are omitted when an ordinary LAN address exists, but can support a genuine carrier-shared LAN when alone. An explicitly named Hyper-V external switch is allowed because it can carry the physical LAN connection. Manual connections are unchanged.

Each eligible interface has an explicit multicast route and advertises only its own local IPv4 address. This prevents a phone on Wi-Fi from resolving an unrelated Ethernet/VPN address. Interface changes are reconciled every five seconds and before outgoing discovery packets. With no eligible LAN, no automatic address or default-route multicast socket is offered.

Device bearer tokens are random, hashed in desktop SQLite and kept in Android secure storage. They authorize the remote/media surface, not the general settings/filesystem API. Audio copies go through the bounded, checksummed `/api/remote/files` endpoint and promote matching placeholders in place. QR images are generated locally. The transport is intended for a trusted LAN; it does not add TLS to the existing HTTP server.

The interface policy has automated pairing/discovery and Cast regression coverage (`node --test scripts/link-lan-discovery.test.cjs scripts/cast-discovery.test.mjs`). Explicit interface binding has also been checked with real multicast query/response on loopback. Physical Windows/VPN and phone network validation remains separate.

## Phone → PC file names

New uploads keep the Android source file's basename when it is available and valid, e.g. `02 - Love Somebody.flac`. Older mobile versions do not send filenames, so the desktop uses the imported artist and title, e.g. `The Motion Epic - Love Somebody.flac`. Names are sanitized for Windows and never overwrite existing music: conflicts receive a numbered suffix (` (2)`, ` (3)`, etc.). The checksum, audio tags, song ID, playlist membership, and likes are unchanged.

Older phone uploads under `data/phone-downloads` used UUID-only names. During desktop database initialization, existing UUID-named imports in that exact folder are relinked to readable `Artist - Title.ext` names and their database paths updated in place. This process retains their existing track IDs, metadata, and audio bytes. Other library folders are not touched. If the original storage filesystem rejects hard links, it leaves the old file and path intact rather than risking loss.

Regression checks: `npm run test:phone-copy`. The linked Android change adds `originalFilename` to the authenticated upload metadata before any temporary staging; the desktop fix remains compatible with older phones.

## Reconnection and saved pairing

Pair tokens have no idle expiry. They survive desktop restarts in SQLite and stay in the phone's secure storage until explicitly forgotten, revoked or replaced by pairing again. A temporary network outage, sleep or profile change is not an unlink. The mobile client retries unavailable peers and reopens the connection when returning from the background; the OS can still suspend network traffic while the phone sleeps.

If the original QR address stops working after a DHCP or interface change, updated mobile clients rediscover the same desktop ID. Before sending a bearer to a new address, the client posts a fresh 32-byte hex challenge and its phone device ID to the local-only `/api/remote/identity` endpoint. With Phone Remote enabled and the paired user active, the desktop returns `{desktopId,userId,proof}`. The proof is HMAC-SHA256 using the stored token's SHA256 bytes as key and UTF-8 `JSON.stringify(['lokal-link-identity-v1', challenge, desktopId, deviceId, userId])` as message. No token or stored verifier is returned. Revoked phones and other active profiles cannot obtain a proof. This verifies a discovery hint within the existing trusted-LAN transport; it does not add TLS or protect against an active LAN relay.

Only a verified address is persisted. Pairing identity, bearer, approved merge and sync cursors remain intact. An old reconnect callback cannot restore a forgotten or replaced pairing. Address recovery requires this endpoint on desktop; an older desktop remains usable at its saved address. Regression checks: `node --experimental-sqlite --test scripts/link-persistence.test.mjs` plus the mobile link identity, socket, credential-store and provider tests. Physical overnight iOS/Android reconnection remains a separate device check.
